# GitHub identity routing

Team Harness supports operator-owned GitHub identity routes in all three
runtimes. Routes map an absolute workspace prefix and GitHub host to an account.
They never contain token values.

## Native config paths

| Runtime | Settings document |
|---|---|
| Claude Code | `~/.claude/.team-harness.json` |
| Codex | `${CODEX_HOME:-$HOME/.codex}/.team-harness.json` |
| opencode | `${OPENCODE_CONFIG_DIR:-$HOME/.config/opencode}/.team-harness.json` |

Each document uses the same schema:

```json
{
  "github": {
    "account_routes": [
      {
        "workspace": "/absolute/workspace/prefix",
        "host": "github.com",
        "account": "github-login",
        "config_dir": "/optional/isolated/GH_CONFIG_DIR"
      }
    ]
  }
}
```

`workspace`, `host`, and `account` are required. `config_dir` is optional.
Resolution canonicalizes the repository root, filters routes by host and path
containment, and selects the longest matching workspace prefix. Duplicate
host/workspace entries are invalid.

## Identity strategies

An isolated `config_dir` is preferred. It contains a `hosts.yml` provisioned by
the operator through `GH_CONFIG_DIR=<dir> gh auth login`. Team Harness records
only the directory path. It requires a private directory outside every git
worktree and a regular `hosts.yml` at mode `0600`. Delivery pins the returned
`GH_CONFIG_DIR` on every related `git` and `gh` process, so concurrent runtimes
do not mutate one shared active account.

Without `config_dir`, delivery uses the existing multi-account gh store. It
checks the active login, runs `gh auth switch` only when necessary, verifies the
effective login, and serializes GitHub writes for that host. This compatibility
strategy may require a scoped sandbox or credential-store approval.

## Security boundaries

- Setup and resolution accept account names, hostnames, and paths only.
- Token-shaped input is rejected; `hosts.yml` bytes are never read or copied.
- Repository content cannot select an identity. Only the runtime-native private
  settings document participates in route resolution.
- A route selects identity but never authorizes push, PR mutation, merge, tag,
  release, or another outward action.
- Successful authentication with the wrong active account is an identity
  mismatch, not a reason to refresh or replace the token.

The canonical helper is
`skills/setup/scripts/manage_github_identities.py`. The Codex and opencode
copies are generated byte-for-byte by `tools/codex-runtime/sync-skills.mjs`.
