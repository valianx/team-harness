# Reload Team Harness in Pi

Activate the already installed Pi-owned TH package in the current primary
session. Bind its absolute root, version/source, active session and selected
agent directory from native metadata or a verified update result. Never choose
the newest cache directory. Reload does not install, update or repair packages,
write TH preferences, change credentials or replace the selected model/thinking.

Use Pi's native `/reload` command, or an actually available public
`ctx.reload()` at a supported extension-command boundary in this same backend.
A slash command written as prose is not an executed refresh. If no callable
control is exposed, report that pending native action and its supported user
entrypoint; do not launch a second Pi process as evidence of refreshing this
session. Respect an explicit no-restart constraint.

Native reload replaces the extension runtime. Do not reuse stale extension
contexts after awaiting it. Let the TH extension restore only verified owned
worker/session associations; uncertain work remains interrupted and is never
automatically replayed. Do not delete sessions or reset coordination records to
manufacture a clean activation result.

Verify the active backend's TH extension/tool discovery, `th-*` skills and the
instructions/resources needed for the current request. Read settings from the
same native agent root without seeding defaults. Check affected provider
resources through Pi's actual discovery; a provider package directory alone
does not prove an available method. Configured Space IDs remain the same when
native Space operations are unavailable, with that precise gap retained.

Keep refreshed files, discovered resources and verified live behavior distinct.
Harmless discovery/status evidence does not prove a model-backed worker run or
an OS sandbox. Preserve successful evidence for unchanged components on the
same backend and report unverified components explicitly. Propose a narrower
reconnect only for an observed stale component or a documented native
limitation after available refresh controls have been used.
