## Why

Team Harness currently treats retained context as a directory, so a native Space cannot remain the effort's working home across planning, investigation, implementation and handoff. Operators need one reusable effort beneath their verified `workspace` Page, while existing local and Obsidian efforts retain their identities and behavior.

## What Changes

- Add canonical `workspace-mode: local | obsidian | gpt-space` selection with explicit legacy precedence, compatible file-mode writes and preservation through setup, import and update.
- Separate the context locator, repository/worktree and optional local operational directory. Preserve v1 file identities and formulas; remote IDs never become filesystem roots.
- Resolve and reuse a verified native Space container and source-bound effort. Main maintains useful context during work through native guarded operations, readback and reconciliation of uncertain writes.
- Route plans, specialist returns, provider results, continuity and immutable review captures through the selected context without a second Markdown home.
- Report invalid selection, unavailable capability, incomplete discovery and partial setup explicitly, preserving the bound identity.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `workspace-canonical-local`: Three-mode selection, separate locators, source-bound reuse, guarded persistence and operational-file boundaries.
- `codex-runtime-parity`: Native setup verification, preference preservation and explicit release/host compatibility.
- `native-workflow-entry`: Hook selection and output confinement for remote or invalid preferences.
- `spec-direct-lane`: A lightweight plan within the selected effort Page, retaining canonical task and source links.
- `external-verification-workflows`: Selected context plus scoped file output for upstream providers.
- `review-context-grounding`: Frozen, provenance-bound captures of selected complete Page blocks.

## Impact

Changes affect shared workspace/continuity helpers, native configuration and installer paths, observational hooks, review capture, existing workflow/role contracts and their generated projections. Maintained Node, Python, Go and hook suites cover executable behavior; current Codex Pages operations establish the native journey. No new dependency or service is required. The delivering minor release is the minimum version for remote mode; unsupported hosts preserve remote configuration and report unavailable capability.

## Non-Goals

Moving or deleting existing efforts or documentation; changing sharing or access policy; offline edit queues; automatic remote precompact writes; cross-host connector provisioning; a filesystem transport, universal index or coordination engine; Pi work or unrelated audit repairs. No database or frontend changes are proposed, so data-model and wireframe previews are not applicable.
