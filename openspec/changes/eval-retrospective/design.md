## Context

See proposal.md for the remaining issue #700 objective. Eval's scenario modes already define invocation, scoring and baseline behavior; hookify provides scoped retrospective evidence and practical friction recommendations. Eval has generated Codex/OpenCode projections and no manual override.

## Goals / Non-Goals

Implement the workflow-retrospective contract as a conditional method owned by eval. Preserve the existing scenario modes and native authority; do not build a runner, state ledger or new evaluator role.

## Decisions

- Select `--retrospective [workspace-path]` and unambiguous completed-effort intent before agent-name parsing. A new standalone skill would split the requested eval owner; inferring retrospect from any path/name would collide with existing scenarios.
- Keep the entry short and place the conditional assessment in `skills/eval/references/retrospective.md`. Reuse workspace association, hookify's evidence/friction method and shared audit finding/evidence semantics instead of copying another whole audit.
- Read the original objective and accepted amendments, reports, review/correction identities and actual delivery evidence. Reject execution-mode combinations; allow a read-only dry-run preview. The result is one factual report, not a universal score or a new source of workflow authority.
- Treat work as duplicate only when its question and relevant inputs support that conclusion. Missing observations stay unknown; changed inputs and meaningful independent advice can justify repeated-looking work.
- Update only the nearest discovery and related unsupported Suite 95/fixed-cost claims. Preserve scenario flags, pass-bar, baseline schema and report formats. Generate all runtime siblings and coordinate one `3.47.0` version bump.

## Risks / Trade-offs

- Historical artifacts can omit or contradict observations → preserve provenance, uncertainty and the smallest missing observation instead of rerunning the effort.
- An agent could confuse retrospective intent with scenario execution → route before scaffold/invocation and check incompatible selectors contextually.
- Source review and distribution checks do not prove live model behavior → report those limits and commission no implicit benchmark.
- A report default could overwrite an evaluated artifact → honor requested destinations and retain useful existing results rather than treating them as disposable scratch.

## Migration Plan

Publish through ordinary canonical skill synchronization; existing invocations need no migration. Living specs capture the new capability. Validation reuses unchanged test-quality evidence, runs current mechanical checks, traces the new intent and verifies implementation before retirement and final advisory review. Local completion is the current authorized endpoint.
