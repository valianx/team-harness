## Why

Current eval modes execute authored agent scenarios but cannot assess an existing completed effort from its retained evidence. Issue #700's remaining improvement needs a retrospective route that identifies factual coverage, claim, consolidation and delivery gaps without rerunning the work.

## What Changes

- Add explicit and contextual retrospective selection before eval's existing scenario routing, preserving Modes 1–5 and their arguments.
- Assess the requested effort's artifacts against its objective and accepted scope, reusing hookify's evidence and friction guidance.
- Produce one evidence-linked evaluation of coverage, claim fidelity, duplicate work, consolidation, delivery and omissions, with actionable recommendations and visible unknowns.
- Keep retrospective analysis separate from agent invocations, benchmarks, baselines, repairs, provider actions and outward publication.
- Update minimal discovery, correct related unsupported verification/cost claims and generate native skill projections.

## Capabilities

### New Capabilities

- `workflow-retrospective`: factual assessment of an existing effort using retained artifacts and explicit evidence limits.

### Modified Capabilities

None.

## Impact

Canonical eval and its conditional reference, existing eval scenario guidance, nearest discovery, generated Codex/OpenCode projections, living specs and coordinated release metadata. Working reports remain in the existing external workspace.

## Non-Goals

Running model benchmarks or the workflows being evaluated, generating new scenarios, changing existing scenario/pass-bar/baseline semantics, creating another evaluator engine or authority ledger, auditing product code, changing permissions, applying recommendations, installing the new development snapshot or publishing another PR without scoped authorization.
