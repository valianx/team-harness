## Why

Project audits currently require separate requests for architecture, bugs, security and other lenses, with inconsistent consolidation and delivery. A complete analysis needs one entrypoint and one useful report, while preserving focused diagnostics.

## What Changes

- Add `full-audit` for one or several repositories, with applicable specialist analysis and one consolidated report including improvements and optimizations.
- Strengthen existing audit coverage, causal findings, reproduction limits and requested artifact delivery instead of duplicating these methods.
- Retain `cross-repo` for its referenced contract/invariant analysis, remove its fixed reviewer quota and synchronize its OpenCode domain workflow automatically.
- Publish the skill through existing discovery and generated runtime projections.

## Capabilities

### New Capabilities

- `full-project-audit`: coordinated analysis, applicable coverage and one integral report.

### Modified Capabilities

- `quality-diagnosis`: complete capability traces, causal findings and focused cross-repository contracts.
- `contextual-ui-design`: analysis-only task/state evaluation with explicit usability evidence limits.
- `document-writing`: requested grouping and verified artifact delivery.

## Impact

Canonical audit-related skills/references, discovery, runtime skill synchronization, living specs and release metadata. Existing focused invocations remain available. Working evidence stays in the established external workspace.

## Non-Goals

Product repairs, provider configuration, production load, external publication, installation into user runtimes, a new orchestrator or workflow state schema, retrospective `eval` expansion and paid model benchmarks.
