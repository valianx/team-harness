## Context

See proposal.md for the objective. Existing audit, bug, security and UI methods already supply focused evidence. Research-code and shared research routing select cross-repo for contract/invariant questions; removing it would discard an identified function. Its manual OpenCode override omits the canonical profile/flow and output methods.

## Goals / Non-Goals

Keep one coordinator, one effort and one principal report. Preserve focused direct invocations and upstream-owned methods. The independent retrospective eval expansion is deferred; this change does not claim to complete every part of issue #700.

## Decisions

- Add a small `full-audit` routing/result contract and put applicability, findings and consolidation guidance in `skills/audit/references/project-audit.md`. Existing owning methods link to it where useful; no second orchestrator or state schema is introduced.
- Preserve cross-repo as a focused contract/invariant audit, with native bounded questions and operator-provided profile/flow inputs. Full-audit selects that method for relevant seams without creating another whole audit.
- Remove the unnecessary OpenCode domain override. Generated projection and a synthetic drift regression keep canonical changes attributable across runtimes. Preserve genuinely manual lifecycle adapters such as Codex deliver.
- Use one `00-full-audit.md`, integrating improvement priorities and optimizations; retain evidence and useful annexes without mandatory separate publications.
- Put action-specific artifact delivery in the existing deliver reference; format/provider owners execute their methods. UI receives an analysis-only endpoint without copying Impeccable playbooks.

## Risks / Trade-offs

- Prose contracts do not prove live model behavior → review concrete scenarios independently and report structural/runtime checks separately.
- Operator profiles are not shipped → resolve explicit/profile-directory context and report exact missing inputs.
- Retained cross-repo may still overlap in name → discovery explains its focused role and full-audit owns the comprehensive outcome.
- New shared references may grow context → load them only for the assigned diagnostic question and avoid repeated reports.

## Migration Plan

Generate normal skill projections after canonical edits and transition the former OpenCode override to generated ownership. Existing cross-repo invocations, focus/output/workspace/profile/flow options remain recognizable. No consumer installation is performed in this task. Synchronize living requirements through the normal OpenSpec archive lifecycle and retain execution evidence outside the repository.
