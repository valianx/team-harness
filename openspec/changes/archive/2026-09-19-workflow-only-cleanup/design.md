## Approach

Retire enforcement at its canonical sources and generation edges, not by disabling native permission settings. Claude keeps its context/observation registrations. Codex stops shipping the TH permission-hook chain. OpenCode keeps its current installer and shared session-context capability; its disconnected guard adapters have no retained consumer after retirement.

Remove exclusive guard bodies, entry points, bundles, lexical helpers and tests only after checking consumers. Keep the normal hook shim, session composer, language, traces, notifications and precompact recovery. Generator checks must detect stale removed outputs while remaining usable for skills and roles. Current setup/update must stop requiring retired hook files and must not translate their regex policies into user-native allow/deny rules. Retain friction analysis through `hookify` as report-only workflow/native-capability recommendations, without instructions to recreate retired TH guards.

The Go Claude managed-block writer has no callers; removing it does not affect current skill-managed voice/discovery blocks or the ownership ledger. Historical cleanup remains conservative: only attributed unmodified TH artifacts can be removed; custom or uncertain files remain visible as pending migration. No automatic restart is inferred from a source deletion.

## Coordination

Reuse `simplify-native-pr-review` for selected-role readiness, advisory specialist returns and Main-owned consolidation. Existing review identity, independent evidence, regression investigation and publication authorization remain useful workflow methods. This change does not remove the pipeline's recovery log or ownership discipline merely because those are called contracts.

## Spec reconciliation

Replace the living Codex deny-floor and dev-guard requirements explicitly. Amend the collaboration-context requirement to separate preserved methods from retired enforcement. `fix-readable-delete-guard` becomes wholly superseded and is retired without applying its policy delta. The old `codex-hooks-powershell-launch` record is mixed: its hook requirement is superseded, while complete agent-roster installation remains supported and must be preserved in living specs before that change closes. Do not reapply old hook requirements during archival.

The PR-review change already reconciles the shared verifier requirement with `pr-regression-evidence`; retain that evidence. Runtime fixture and configuration checks establish supported adapter behavior, not live-host security equivalence or measured performance. Reports and review transcripts stay in the existing Obsidian workspace.

## Verification

Check absence of permission registrations/generated leftovers and preservation of context/observation behavior. Exercise fresh and repeated setup/update fixtures; run Codex generation/distribution, OpenCode transformations, installer tests and retained session/parity suites. Run the complete repository suite after integrating its retirement updates. Review the final candidate with independent QA, security and adversary assignments; Main verifies repairs without replacing original verdicts.
