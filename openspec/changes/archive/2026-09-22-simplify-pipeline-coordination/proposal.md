## Why

Mandatory validation and publication delegates make the spec lane another pipeline. Existing pipeline specialists also retain v4 report, Freeze and approval requirements that conflict with today's native coordination and cause repeated work. The operator wants a lightweight spec lane, a simpler existing pipeline and effective independent reviewers.

## What Changes

- Keep spec execution with the principal through implementation, validation and create-pr, retaining independent review and applicable verification tools.
- Retire the unpublished spec-validator/pr-creator roles and their special runtime mappings; reuse existing pipeline specialists and native model selection.
- Simplify active pipeline assignments and results to useful context, owned work, actual evidence and findings. Reuse sessions and unaffected checks, and batch coherent work instead of spawning by phase or checklist item.
- Align implementation/test ownership, delivery and native adapters with the current pipeline; remove obsolete report prerequisites, mandatory task commits and return schemas from these active roles.
- Preserve existing reviewer models, independent findings, OpenSpec/sketches, local/Obsidian workspace, artifact hygiene and authorized publication.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `spec-direct-lane`: principal execution with independent advice, without required completion delegates.
- `specialist-coordination-protocol`: coherent native assignments and useful results across existing pipeline roles.
- `pipeline-control-plane`: dependency-aware coordination and delivery without obsolete phase contracts.
- `codex-runtime-parity`: remove unpublished completion-role exceptions and align adapters with retained roles.

## Non-Goals

No replacement harness, new scheduler or state schema, global model change, reduction in selected review coverage, broad deletion of compatibility tooling, or rewrite of unrelated workflows. No new database or frontend surface.

## Impact

Canonical skills, active pipeline roles and Codex adapters, shared coordination/delivery guidance, documentation and generated distributions. Runtime code introduced solely for the superseded completion roles is removed; existing model settings and explicit overrides remain supported. This is an authorized amendment of archived `delegate-spec-validation-and-pr`; its original history and evidence remain retained. The final PR describes the lightweight spec and simplified pipeline outcome.
