## Why

The TH 3.56.0 audit found eleven mismatches between workflow contracts and their consumers. Updates can replace partial operator preferences, review ranges can describe different comparisons, installed skills can resolve the wrong configuration or miss required resources, and current documentation still prescribes retired behavior. Diagram labels can also sit below their SVG routes despite valid geometry.

## What Changes

- Preserve configured Codex fallback fields and check the required Python version before native installation changes.
- Bind review scope and coordinates to one immutable effective comparison.
- Resolve installed asset/configuration roots and supply required runtime documentation in OpenCode.
- Align installation examples, update recovery and current planning/ownership guidance with the implemented flows.
- Keep relationship labels visible and clickable above routes in the copied diagram kit.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `codex-update-convergence`: prerequisite checks and preservation of partial custom defaults.
- `guided-lane-verification`: consistent immutable coordinates for accepted review ranges.
- `native-workflow-entry`: installed resource/configuration resolution and current operator/contributor instructions.
- `source-driven-architecture-diagrams`: relationship-label paint order and pointer access.

## Impact

Codex update/setup helpers, review packaging, shared skill projection and native installer manifests, the diagram starter, maintained regression cases, living specifications and the affected usage guides. Runtime distributions and release metadata remain generated from their canonical inputs.

## Non-Goals

New workflow modes, provider/model policy changes, cloud execution, personal configuration edits, presentation changes, another live-model trial, or guaranteed readability of arbitrary dense diagrams. The endpoint is a reviewed published PR; merge and local installation are separate actions.
