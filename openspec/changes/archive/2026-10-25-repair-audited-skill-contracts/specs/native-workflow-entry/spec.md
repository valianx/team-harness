## MODIFIED Requirements

### Requirement: Active guidance describes supported coordination
Active entrypoints and public installation/workflow documentation SHALL agree with current native installation, four-phase coordination and advisory review. They SHALL NOT require retired gate records, a fixed reviewer or research team, a universal coverage percentage, or a restart without a demonstrated native need. Migration guidance SHALL preserve custom commands and settings.

Current installation and recovery examples SHALL deliver configuration to the process that consumes it, include required snapshot download steps and preserve operator-owned edits according to the selected update method. Historical planning formats SHALL be identified as compatibility material rather than requirements for new work.

#### Scenario: An operator follows auxiliary issue or testing guidance
- **WHEN** work begins through a supported auxiliary skill
- **THEN** useful workflow routing remains available and Main selects proportionate work without obsolete mandatory teams or gates.

#### Scenario: An old installation contains custom commands
- **WHEN** the operator follows migration documentation
- **THEN** only verified TH-owned content is eligible for removal and generic wildcard deletion is not prescribed.

#### Scenario: A selected reviewer cannot obtain native read-only isolation
- **WHEN** a supported native read-only alternative cannot recover the selected review
- **THEN** Main records incomplete coverage without manufacturing a pass, preserves native permissions and decides delivery under existing operator authorization; only an explicit unmet operator condition requires a new decision.

#### Scenario: An operator copies the optional MCP installation example
- **WHEN** optional MCP values are supplied using the documented Unix pipeline
- **THEN** the installer process receives those selected values

#### Scenario: An installed plugin needs a newer snapshot
- **WHEN** an operator follows the troubleshooting update path
- **THEN** the guidance selects the supported download and activation flow rather than catalog refresh alone

#### Scenario: A contributor starts a new plan or adds synchronization
- **WHEN** current conventions and maintenance guidance are followed
- **THEN** they use the current OpenSpec/native assignment contracts and operator-edit preservation rules without requiring retired shards, nonces or unconditional force-copy

### Requirement: Maintained entry points agree with their native consumers
GCP cost analysis SHALL run through the current coordinator and its cost specialist
without an undocumented mode or nested coordinator. OpenCode SHALL retain workflow,
language, voice and workspace discovery through its registered native guide;
disconnected context-hook source SHALL NOT be presented as an active integration.

Installed workflows SHALL resolve settings from their selected native installation and include the support resources their methods require. Packaged audits SHALL identify the actual asset tree rather than a skill's discovery metadata directory.

#### Scenario: Cost analysis is selected
- **WHEN** the operator requests costs for named projects or the supported quick/full scope
- **THEN** the current coordinator resolves the workspace and delegates the bounded read-only analysis to the cost specialist

#### Scenario: OpenCode installs or updates TH
- **WHEN** the native guide is registered
- **THEN** collaboration preferences and workspace remain discoverable without requiring the disconnected session-event adapter

#### Scenario: An OpenCode installation uses a nondefault root
- **WHEN** a skill is installed through project scope, an explicit root or an OS-specific configuration root
- **THEN** its settings binding agrees with that selected installation without independently guessing a global path

#### Scenario: A standalone installation invokes a documented method
- **WHEN** an installed workflow requires a distributed supporting method document
- **THEN** that document is included and resolvable without a Team Harness source checkout

#### Scenario: A Codex skill has native agent metadata
- **WHEN** a packaged self-scan is invoked without an explicit asset root
- **THEN** the scanner selects the package's actual agent asset tree instead of the skill's metadata directory
