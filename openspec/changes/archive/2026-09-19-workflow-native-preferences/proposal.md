## Why

Team Harness should teach a useful way of working while the native agent and operator retain execution policy. After retiring permission hooks, Codex setup/update still treat TH's sandbox, approval, network and writable-root defaults as mandatory, and several skills repeat confirmations, routing and helper procedures.

## What Changes

- Preserve native execution preferences during ordinary setup/update; remove the automatic runtime-profile reconciliation and its approval ceremony. Keep agent installation, workflow discovery, preferences, workspace/Obsidian routing and honest access diagnostics.
- Let the current general agent coordinate audit and research. Reuse explicit authorization for a bounded local handoff rather than asking for it twice.
- Consolidate Verify, spec and specialist-return instructions around their maintained contracts; remove unused activation metadata without removing recovery, candidate identity or independent review.
- Retire disconnected Codex-hook fixtures and a superseded probe while retaining useful historical conclusions and active validators.

## Capabilities

### Modified Capabilities

- `codex-update-convergence`: update converges TH components without classifying or changing native execution policy.
- `codex-runtime-parity`: setup/update preserve native preferences; workspace access diagnosis does not prescribe policy replacement or automatic restart.
- `native-workflow-entry`: the native coordinator uses concise skills and existing task authorization while preserving collaboration context.

## Impact

Codex setup/update helpers, generated project defaults, shared workflow contracts, documentation and their distributed projections. The convergence receipt will describe only retained installation domains; the installed skill defines its versioned contract. Existing native configuration is preserved, including values previously installed by TH. Reusable behavior tests cover policy preservation, installation and workspace integration.

## Non-Goals

Changing the user's live permissions, removing reviewer read-only defaults, replacing the pipeline state machine, redesigning GCP destructive-operation authorization, deleting OpenSpec history, removing migrations with consumers, or claiming complete live-host reload or measured performance gains.
