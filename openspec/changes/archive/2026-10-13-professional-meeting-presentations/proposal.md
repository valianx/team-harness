## Why

The existing interactive-presentation workflow compiles scenes but does not establish meeting-ready composition or verify rendered results. Permanent chrome, unguarded keyboard navigation and disconnected animation transport reduce the usable stage and can disrupt a live presentation.

## What Changes

- Extend the existing entry to create meeting presentations or improve existing decks, retaining `new`, `add-scene` and `from-ppt` compatibility.
- Establish narrative and contextual visual direction through `ui-design`, preserving incumbent identity and factual content during improvement.
- Read the maintained frontend-slides workflow outside the product for straightforward new HTML presentations; retain incumbent engines and React Flow/GSAP for complex interactive content.
- Use a maintained presentation engine for new complex React scaffolds rather than recreating navigation or presenter synchronization.
- Compose a clean audience stage with discreet accessible overlay controls, focus-aware slide/step navigation and transport connected to actual animations.
- Require meaningful browser checks of composition, interaction and motion at meeting viewports, with truthful evidence and limitations.

## Capabilities

### New Capabilities

- `professional-meeting-presentations`: creation and improvement of web decks for live meetings, covering context, upstream reuse, stage composition, controls, navigation, animation and rendered verification.

### Modified Capabilities

None. Existing contextual-ui-design and workflow discovery contracts remain sufficient; this change uses their established behavior.

## Impact

Canonical scope is `skills/interactive-presentation/`, its maintained templates and references, focused tests and installer template-completeness coverage. Codex/OpenCode skill copies remain generated. New complex React scaffolds select `@revealjs/react` with `reveal.js`; package compatibility and interaction behavior must be verified. Existing decks retain their engines. Release metadata and any accurate discovery copy updates accompany delivery without new role inputs.

## Non-Goals

No second presentation skill, vendored upstream catalog, forced framework migration, custom presenter synchronization, automatic deck publication, unsolicited inline editing/export, database change or live-model benchmark. This change improves the workflow and reusable template, not a particular operator's final deck.
