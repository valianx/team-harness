## Why

Pipeline specialists still carry broad, overlapping checklists after the inline reviewer was shortened. Spec also repeats routing, context recovery and evidence accounting across stages, increasing work without establishing additional confidence.

## What Changes

- Give pipeline QA, security and tester short roles driven by a bounded assignment and current evidence.
- Use one independent assessment per selected question; reuse it at final review instead of dispatching an equivalent second reviewer.
- Give shared phase guidance one owner; reuse resolved providers and existing evidence without repeating discovery or administrative reports.
- Align the affected living specifications with advisory reviews and targeted corrections.
- End PR descriptions with a single descriptive true/false risk flag in the PR's language.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `specialist-coordination-protocol`: concise assignments and scoped context for specialists.
- `pipeline-control-plane`: one independent assessment per selected question across workflow handoffs.
- `spec-direct-lane`: reuse workflow context and report each provider outcome once while preserving all current stages.
- `four-phase-development`: a concise localized risk footer for PR delivery.

## Impact

Canonical roles, workflow instructions and Codex adapters; generated Claude/Codex/OpenCode distributions; relevant specifications and contributor-facing workflow documentation. No new runtime dependency or enforcement helper.

## Non-Goals

Changing models, removing independent review or mandatory OpenSpec implementation verification, replacing external tools, changing PR-review publication, or claiming measured cost savings without comparable runs.
