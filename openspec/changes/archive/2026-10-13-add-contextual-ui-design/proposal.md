## Why

UI work repeatedly produces generic presentation and palettes that do not fit the application's users, tasks, content or established identity. Team Harness needs a direct visual-design entry that grounds decisions in the actual product and uses a maintained specialist workflow.

## What Changes

- Add portable `ui-design` for new UI, refinement and explicitly requested redesign, coordinated by the current general agent through Impeccable.
- Derive task hierarchy and visual direction from the product, incumbent components, tokens, assets and supplied references; preserve established brand and stack within authorized scope.
- Research relevant internet references when identity or color direction is unsettled or replaced, retaining adaptation reasons and comparing alternatives on an actual representative screen only when a material direction remains open.
- End design-only work at a reviewable visual result. Continue explicitly requested implementation through existing sketches, scoped changes and rendered validation without another blanket approval.
- Prepare only the selected active-runtime Impeccable capability through its official owner route and report dependency, discovery, usability and evidence limits separately.
- Expose the entry in public discovery and generated Codex/OpenCode distributions.

## Capabilities

### New Capabilities

- `contextual-ui-design`: Product-grounded visual design, selected upstream preparation, continuity and evidence.

### Modified Capabilities

- `native-workflow-entry`: Make `ui-design` discoverable without changing agent identity or implicitly activating a pipeline.

## Impact

Canonical `skills/ui-design/SKILL.md`, one dependency reference, existing discovery documents, generated skill projections, affected living specs and synchronized release metadata for minor version `3.44.0`. Impeccable remains an external dependency prepared through its verified official active-runtime route. Existing `design`, `sketch` and `workspace` contracts remain the integration boundary.

## Non-Goals

No vendored design playbook, analyzer, new runtime role, hook, component framework, stack migration, universal palette tournament or mandatory provider setup for unrelated workflows. This change does not design an example application, install Impeccable in the operator's live project, run model benchmarks or claim measured visual-quality improvement.
