## Why

The diagram skill extracts sources faithfully but its first real 20-component output needed substantial operator guidance: a 7,000px compound layout shrank names to about 2.4 screen pixels. The operator wants the skill to make better composition decisions and repair its own visual result before delivery.

## What Changes

- Make compact, readable first composition an explicit authoring responsibility, retaining accepted preferences and source-led contextual styling.
- Give the kit a bounded composition policy that balances graph shape and measured readability instead of accepting the first layered arrangement.
- Preserve the complete architecture, relationship evidence and stable 90% framing while using useful supplementary perspectives.
- Have the agent inspect actual renders, recompose within a bounded loop and retain specific unresolved limitations when no suitable result is found.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `source-driven-architecture-diagrams`: compact composition selection, source-preserving visual revision and first-delivery judgment.

## Impact

Canonical diagram skill guidance, reusable starter layout/measurement/viewer integration, source-driven architecture living requirements and focused executable coverage. Distributed copies are generated from canonical inputs. Existing consumer projects keep their own files; installation updates do not silently replace them.

## Non-Goals

Presentation changes, a new renderer, provider or dependency upgrades, operator-authored JSON/coordinates, global preference storage, additional control designs, unrestricted layout search or live model calls in maintained tests.
