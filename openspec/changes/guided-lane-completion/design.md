# Design — guided-lane-completion

Decisions behind the deltas; each resolves a measured failure or a contradiction between two shipped contracts, not a preference.

## D1. One full-scope pass, then delta-only closure — never a second full scope

The measured pathology is round-count, not dispatch size: 53% of a 6.1M-token run went to correction rounds that each re-opened full scope, and CR-Bench measures reflexive re-review as raising recall slightly while collapsing signal-to-noise from 5.11 to 1.95 — later passes mostly manufacture findings. The opposite failure is equally documented in the same run: fix commits were its most defect-dense, with round-1 fixes changing a mechanism while leaving the property intact and one hygiene defect introduced by the round-4 fix itself, so a lane that never re-checks a fix certifies a tree that stops existing at the first correction. The resolution is asymmetric by construction: full scope runs exactly once, and each applied fix earns exactly one closure pass bounded to that fix's own reopening construction and the files it touched. Closure passes do not accumulate into a round counter and cannot reopen the full surface; a finding outside the fix's own surface is recorded as a pull-request concern, never as a new round. This keeps the recall of an independent first pass and the fix-audit that the pipeline proved indispensable, without the loop that produced the cost.

## D2. A security dimension raises the bar and asks — it does not silently eject or silently absorb

Today any security dimension discovered in flight ejects the whole task to the pipeline. That is expensive and, more importantly, it is the wrong instrument: what earned its cost in the measured run was the adversary lens under a ship-blocking conjunction, not the workspace, gates, events or specialist fan around it. But absorbing a floor by fiat would weaken it, and the floor's own rule is that an ambiguous classification is sensitive. So the lane neither ejects nor absorbs on its own authority: it stops, displays the matching floor category, and presents a live three-way choice — raise the bar in-lane, take the pipeline, or narrow scope. Raising the bar in-lane means `security` and `adversary` join `required_lenses` and the conjunction becomes real: the pull request does not open until both return a pass with no blocker. This mirrors the authority the repository already grants — a sensitive request may stay inline when the current live operator explicitly selects it — and makes the choice explicit rather than implicit. The classes where pipeline machinery itself is the thing needed stay hard routers regardless of the answer: multi-repository work, irreversible work, multi-task scale, and any run intended to proceed operator-absent.

## D3. Review lenses are not specialists

The lane's `multi-specialist` hard router and the review contract's multi-lens package contradict each other: a four-lens request is a normal review package with one reviewer instance per lens, but a conservative reading of "needs a second specialist" bounces it to the pipeline. The rule is stated once, in the lane's own predicate: lens count never counts toward specialist count, because every lens is read-only, returns a verdict rather than an edit, and shares the single anchored target. A second *specialist* means a second agent that writes.

## D4. Written intent binds as criteria, with its own provenance

The review package's criteria carry provenance `live-operator | trusted-policy | inferred-scope`, none of which fits an authored proposal. Verifiers consequently check a diff against whatever the operator typed rather than against the intent the change was approved on. A fourth value, `written-intent`, admits the authored `openspec/changes/<change>/` requirements as criteria while keeping their origin distinguishable in the return — an artifact-derived criterion must remain separable from a live one, because the operator approved the artifact once and cannot be assumed to have re-approved every sentence in it. Binding is by reference to the anchored path, not by pasting content, so the criteria stay verifiable against the committed tree.

## D5. The exclusion lives in artifact construction, and only under locally executed checker evidence

The two-halves rule forbids implementing a review-scope exclusion as dispatch prose or as a clause in any verifier's contract, which leaves exactly one compliant site: the step that builds the frozen artifact. Three preconditions make the exclusion safe rather than merely cheaper. First, eligibility requires a checker run executed locally over the frozen tree and recorded as suite evidence — the parity checkers run in CI on push, while Freeze and validation happen before any push, so a CI-green claim is not available at review time. Second, the same prefix set filters QA's independently derived scan list and the packet's changed-files table, because QA resolves its scan list from live `git diff --name-only` and a path present there but absent from the table sets `packet_integrity: mismatch`. Third, an excluded prefix must be one the checker proves exhaustively: source-driven mirrors do not detect an extra target file with no source counterpart, and `runtime/codex/instructions/**` is verified only by substring assertions, so both stay in review. The exclusion is enumerated in the packet by prefix and line count so a reviewer can see what was removed and why, and a frozen diff that is empty only because everything was excluded is reported as such rather than blocking as an unexpected empty artifact.

## D6. Routing offers the lane presumptively, and the sensitivity authority is repaired before it is relied on

Three sites render the escalation guidance and all of them make the spec lane optional wording — "MAY additionally offer" — which in practice means the cheaper lane is offered only when the coordinator remembers to. The predicate already encodes the eligibility test, so passing it is the reason to offer, and the guidance renders three options whenever it passes. Repairing the sensitivity authority is a precondition of that change rather than a tidy-up: eight canonical sites resolve sensitivity through `docs/pipeline-lanes.md § 2a`, the section was removed, and this change makes the same predicate load-bearing in one more place. The anchor is restored in the file that already owns posture, and the carriers that duplicate the predicate verbatim are updated together with the stale inlined copy in the setup skill, whose own text declares the managed block to be the source of truth.

## D7. Measure what exists; do not manufacture what does not

Per-attempt token components cannot be produced honestly today. On Claude Code the runtime exposes no per-subagent usage the pipeline can read, and the coordinator is explicitly forbidden to split a phase delta, mine transcripts, or estimate; on Codex the collector computes role-labelled per-session components but persisting them is forbidden, attribution from session to declared attempt does not exist, and two of the five required components are not collected at all. So `metrics_status: unavailable` stays correct and this change does not touch it. What is available is being discarded: the coordinator writes `agent.spawn` and `agent.close` with timestamps, so per-attempt wall time is derivable from its own events with no new source, and each dispatch's declared input manifest is a set of files whose size is computable — the deterministic budget that identified the adversary's 114,000-token load as the single largest fixed cost. Both are recorded as what they are, and the gap between the phase totals and the run total is stated as unattributed coordinator overhead rather than left as an unexplained remainder.

## D8. Every rule ships with a producer or a checker; prose alone is not a deliverable

The failure this change is correcting was itself produced by prose: a lane whose review cap and escalation live only as sentences, a sensitivity authority cited by eight files after its section was deleted, and a two-halves rule that no test enforces. Prose rules have no producer and no consumer, so they rot in place and nothing fails when they do — and they are precisely the surface that degrades across runtimes, because the Codex and opencode projections carry adapted prose while carrying the pipeline scripts byte-for-byte. So each requirement here lands as an executable that constructs the artifact the rule governs, or as a deterministic checker that fails when the rule is broken. The review package stops being something a coordinator assembles from memory and becomes the output of `review-fan.mjs`, which derives the changed surface from git, binds the change's validated requirements as criteria, classifies the security floor from the diff rather than from recall, forces the floor's lenses into the required set, refuses to emit a second full-scope package once a prior anchor exists, and decides the ship-blocking join from the returns it is given. The exclusion set stops being a judgement and becomes the output of `review-surface.mjs`, which executes the covering checkers locally and derives eligibility from their own expected file sets, refusing on a skip. Predicate consistency, resolvable section anchors, and the absence of any verifier-side scope clause become assertions in the deterministic suite. What remains in prose is the contract those executables enforce, which is the one thing prose is good for.

## D9. Lane-specific rules live in the lane's file

`agents/_shared/inline-review-contract.md` is already 1,824 words against a 1,500-word shared-contract budget, so this change adds to it only what is genuinely shared: one criteria-provenance value and one sentence separating lens count from specialist count. The closure loop, the three-way security choice and the invocation surface are lane behaviour and live in `skills/spec/SKILL.md` and `skills/verify/SKILL.md`, which point at the shared contract rather than restating it. This also keeps the one-canonical-home rule intact for the review package schema.
