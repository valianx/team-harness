## Context

See proposal.md for motivation. The current branch added two direct/spec completion agents but has not been published. The operator now explicitly selects a lightweight spec lane and improvements to the existing pipeline. Its short coordinator guidance conflicts with specialist prompts that still require v4 reports, Freeze identities, narrow read manifests and fixed result blocks.

## Goals / Non-Goals

Keep one current principal and the existing independent reviewers. Make reusable skills describe phase work while native assignments carry only the context needed for useful delegation. Preserve supported runtimes, declared tools, operator model choices and working verification. This amendment changes coordination, not the models used to judge quality.

Do not replace historical helper APIs or rewrite unrelated flows. Do not create a scheduler, universal result schema, new model resolver or tests that assert prose wording. The selected local/Obsidian workspace remains the evidence home.

## Decisions

1. Remove the unpublished completion roles and their exclusive generator/converter/install logic; keep their archived intent as superseded history and apply this explicit amendment. Keeping the roles as another default would perpetuate the duplicate pipeline.
2. Spec performs its four phases in the current chat and invokes applicable reviewers. Existing skills own validation and PR preparation/publication. A phase transition does not require an executor handoff.
3. Pipeline assigns coherent work according to real dependencies and ownership. Main may finish a small step itself. Reuse the current executor for relevant corrections; parallelize genuinely independent work. Role availability is not a requirement to invoke every role.
4. Align canonical architect/implementer/tester/cleaner/QA/security/delivery prompts and Codex adapters. Implementers can own ordinary tests; testers provide additional expertise. Keep independent review, read-only reviewer boundaries, meaningful findings and verification of corrections. Delivery consumes current evidence through create-pr and can recover missing factual context without requiring obsolete reports or restarting validation for metadata-only work.
5. Keep existing native model settings and overrides while reducing coordination overhead. Avoid changing reviewer quality and workflow topology together; model tuning remains a separate measured decision.
6. Update canonical inputs and generate distributions. Validate executable role configuration, transformed install assets and artifact lifecycle with existing suites; review prose by reading it against concrete scenarios. Reuse unaffected evidence and record limits instead of simulating live hosts.

## Risks / Trade-offs

- Removing detailed prose can remove useful expertise: review the retained role goals, ownership and evidence obligations independently.
- Legacy documents still exist: remove active dependencies on obsolete requirements, retain historical readers, and disclose any unrelated residue rather than broad deletion.
- Native model activation is not proven by generated files: report actual dispatch observations separately from configuration tests.
- No controlled timing comparison exists: report simplification and observed workflow results without claiming a measured percentage saving.

## Migration Plan

Remove only the superseded branch additions, revise current workflow/role sources, regenerate, validate and archive this amendment in the same PR. No consumer workspace migration, global settings change or restart is needed for the written workflow changes. Git history retains rollback and the original candidate evidence remains outside the repository.
