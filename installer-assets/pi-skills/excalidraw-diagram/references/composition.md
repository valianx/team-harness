# Reference-led flow composition

## Extract before drawing

Read supplied documents, images and the current editable scene. Record component occurrences, directed relationships, labels, boundaries and uncertainties with source locators. A repeated actor can close a flow without implying another deployed system. Distinguish approved examples from unapproved drafts; retain their scope in the bound context.

## Arrange a readable flow

- Preserve the approved primary reading axis, supporting-service side and lower response lanes. Folding the primary path or flipping the support side remains an unresolved composition change even when fonts and geometry pass.
- Use consistent, spacious component cards when they communicate equal roles. Keep functional zones visually subordinate; use subtle hatching if the reference calls for it.
- Reserve separate lanes and endpoint slots for requests, returns and different calls to the same service. Plan these together before drawing individual arrows.
- Keep labels close to their own route, on clear segments away from elbows and arrowheads. Route around unrelated cards and labels; show an unmistakable direction at the fitted scale.
- Reserve measured label-mask and arrowhead clearance before drawing a short native connection. Correct label coordinates can still hide the entire arrow; lengthen its clear segment rather than shrink its text.
- Component colors express roles or ownership; relationship colors express interaction classes. Preserve their separate meanings, stroke patterns and contrast.
- Use internal whitespace for lanes and legibility. Fitting the drawing to 90% of the viewport does not mean filling 90% with cards.

For a collection, give each flow an independent start, outcome and boundary. Repeat shared components with common source meaning rather than threading unrelated sections together. Provide an orienting overview and readable per-flow views; a tiny collection image cannot establish label readability.

## Choose and preserve the editable artifact

Honor an explicit engine request. When editable composition is the requested starting point, establish it in Excalidraw and use its accepted scene/reference as input to an optional React Flow reconstruction. Web behavior must be checked in the web viewer; a screenshot establishes neither hover behavior nor native editing.

Read the current approved scene before every revision, retain a recoverable backup and preserve unaffected IDs, annotations, styles and positions. Generators may create drafts; the current human-edited scene is the revision source. Use native bound arrows and reciprocal labels with supported fixed bindings, not disconnected line segments.

## Inspect before delivery

Inspect the actual current revision at its intended fitted view, including 1280×720 and 1440×900 for web output. Check source completeness separately from label size, spacing, zone hierarchy, route separation and direction. Confirm the visible file/model identity after opening or refreshing the intended viewer.

For desktop per-flow presentation, target effective component names of at least 14 CSS px and relationship labels of at least 11 CSS px at those fitted viewports. Correct the arrangement or shared measured typography when below target, and judge the actual captures; collection overviews serve orientation.

Use an initial composition and at most two corrective cycles, retaining each observation and causal change. Measure effective on-screen text and read the captures; a larger PNG improves sharpness without increasing fitted text size. If a required check or readable view remains unresolved, deliver the editable draft with the named limit rather than claiming completion.
