# Coordinator recovery

## Operational repair in every posture

Main must diagnose operational failures and attempt a verifiable repair before
reporting a blocked objective. Contract-format errors, stale paths, missing tools
or libraries, and recoverable transport failures do not require another operator
approval when the repair preserves the approved deliverable, acceptance meaning
and existing authority. Resolve installed paths, restore declared prerequisites
in an isolated environment, or regenerate coordinator-owned derived artifacts
from canonical inputs; verify the repaired condition, then resume pending work.
Never invent missing decision-bearing evidence or silently edit approved intent.

Native permissions still apply. Prefer a permitted local environment repair to
changing shipped dependencies or lockfiles. A repair that changes the deliverable,
security authority, destructive effects or an unapproved outward action needs its
applicable live decision. Preserve valid work; do not repeat the same failed
action without changed evidence. Report a blocker only when no verifiable repair
remains within authority, stating the missing condition and attempted remedies.

## Activated pipeline

Recovery begins by preserving valid progress and proving that the prior writer
is terminal and the canonical worktree has one committing owner. Main then
compares authority, intent/scope/security, immutable inputs, context, ownership,
failed-action identity, safe-next-action identity, and independent-lens needs.

- Continue the same lease and session when all identities and exclusive
  ownership remain valid, context is verifiable, and changed evidence supports
  a safe action with a different causal identity.
- Replace the session only when the lease remains valid but context cannot be
  verified or an independent lens must change.
- Pause after operational diagnosis when ownership/integrity/prerequisites cannot be restored or every known
  action repeats the same causal identity.
- Obtain a live decision when approved meaning, scope, security authority, or an
  outward effect changes.

Counts, ordinals, elapsed time, token use, tool calls, and telemetry never select
these routes. A changed candidate always receives fresh QA. Security is fresh
when impact is true or cannot be proven false. The executable classifier is
`decideCausalRecovery` in `skills/pipeline/scripts/control-plane.mjs`.
