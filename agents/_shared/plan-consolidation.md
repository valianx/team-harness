# Plan and result consolidation (v5)

Canonical OpenSpec owns proposal, scenarios, design decisions, and work tasks.
Design does not compile those semantics into overlays, exhaustive execution
contracts, task shards, or permanent future capsules. Main derives one minimal
capability lease only when a coherent worktree batch becomes dependency-ready;
prompt prose and `01-plan.md` cannot widen or duplicate OpenSpec or lease fields.

`01-plan.md` is a generated read-only operator projection. It carries outcome,
included/excluded scope, approach, coherent batches, material risks and
decisions, preserved behavior, links, and the pinned OpenSpec identity. It
contains no copied AC/TC text, commands, seams, file-by-task graph, or dispatch
schema. OpenSpec changes make it stale and require deterministic regeneration.

Main consolidates only validated, accepted result envelopes. Specialists edit
only lease-owned repository paths. Specialists never edit OpenSpec checkboxes.
Coordinator state, Gate views, finding ledgers, acceptance views, and delivery
state are projections owned by Main.

## Write-tool discipline

Write only lease-owned paths with the runtime's bounded edit tools. Preserve
unrelated changes and never use coordinator files as a specialist output.

## Write-scope on the plan set (closed list)

One architect may author or update proposal, specs, design, and tasks only when
the bound change is missing or the live operator requests a semantic edit.
After approval those sources are immutable to specialists; Main owns all
workspace projections.
