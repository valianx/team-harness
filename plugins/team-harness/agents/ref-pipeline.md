# Team Harness pipeline

Main coordinates under native permissions. Read the needed phase in
`skills/spec/references/development-phases.md` and apply
`skills/spec/references/lifecycle.md`. Keep progress in the selected workspace.

Phases describe work, not permissions. Select capabilities for the objective and
stack; record results, omission reasons and genuine prerequisites. Specialists
provide evidence; Main judges findings and the operator decides scope.

## Working context

Retain OpenSpec intent, task progress and evidence. Existing authorization covers
unchanged work. No TH permission ledger, lease, nonce or result schema is required.

## Spec

Reuse `workspace` in its local or Obsidian mode. Clarify outcomes, scope and
decisions; author or reuse OpenSpec and tasks. Execute the applicable design and
testing strategy. Use `sketch` for required database models and frontend wireframes,
and `plan-review` for requested advice. Keep `01-plan.md` as the working summary.
Continue when implementation is authorized.

## Implementation

Group dependency-ready work by context and ownership under
`agents/_shared/dispatch-contract.md`. Parallelize independent assignments;
serialize overlapping edits and Git mutations. Implementers own ordinary tests;
testers and cleaners add expertise when useful. Verify progress against actual
changes and checks.

Reuse an executor for related corrections. Main may complete small steps directly;
roles are expertise, not mandatory stops. Retain native model settings and honor
supported operator overrides.

## Validation

Run selected project checks and provider assessments, including real CRAP when
inputs apply. Use TEA review/trace, OpenSpec verify, Superpowers verification and
selected independent reviewers. Retain evidence and limitations in the workspace.

After implementation verification, synchronize living specs and prepare the
completed archive on the delivery branch. Anchor candidate review, honor selected
coverage and preserve original findings. Main resolves concrete defects and
verifies corrections, renewing affected evidence without restarting unrelated work.

## Publication

Use `create-pr` to prepare and publish the authorized candidate with its archive,
current evidence and artifact hygiene. Main normally executes publication; an
assigned delivery specialist uses the same method. Recover relevant missing
context without demanding legacy reports or another acceptance matrix.

For metadata corrections, renew affected checks and preserve applicable authority.
Publication does not imply merge, release or installation. Native permission
prompts still apply. Historical Freeze/Gates records remain readable but do not
control current work.

## Failures and recovery

Use `agents/_shared/coordinator-recovery.md`: diagnose, repair prerequisites or
change approach while preserving successful work. Resolve the existing workspace
and inspect its plan, tasks, Git state and handoff. Missing legacy files do not
force closure; report corrupt records as unverified and continue from trustworthy
sources. Confirm overlapping writers stopped before reassignment.

Preserve unrelated work, safe file handling and honest evidence. Report genuine
unresolved dependencies without inventing success or another execution harness.
