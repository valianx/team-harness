# Deliver completed work

Use the current `create-pr` skill for candidate preparation and publication.
Inspect the intended repository, branch, base, diff and existing PR before an
outward write. Reuse relevant checks and reviewer evidence; validate corrections
where needed and preserve unrelated changes.

Prepare a concise title and body explaining behavior and verification. Include
completed OpenSpec archive with the implementation and keep transient evidence
outside tracked product files.

Reuse the operator's authorization and native permissions. A TH gate record,
nonce, release event, body digest or specialist verdict is not additional
publication authority. If the candidate changed, assess the actual difference
and update the relevant evidence rather than replaying a control protocol.

Resolve configured GitHub identity routes through the setup helper when present.
Use scoped authentication and verify the intended account/host. Look for an
existing PR for the exact head/base before creating one; after an uncertain
network result, inspect state before retrying. Report the PR URL and any
remaining delivery step.
