# Cloudflare security

Use the maintained Cloudflare `security-audit` workflow for the selected target.
Main coordinates through the active runtime's native tools and permissions.

## Prepare the selected capability

Read [provider preparation](references/provider.md). Resolve the runtime, target
repository, installation owner, scope and actual installed instructions. Reuse
a healthy installation. An explicit `install` or `setup` request prepares the
provider and returns its readiness. An explicit `update` refreshes the selected
provider through its owner and returns the result.

TH setup/update accepts the explicit `cloudflare-security` target. Ordinary TH
maintenance keeps this optional provider on its own lifecycle.

## Apply the installed method

For security work, read the installed upstream `SKILL.md` and only its relevant
companion references. Pass the target/source revision, question, scope, relevant
prior evidence, authorized effects, output destination and any budget. Follow
its guidance mode for questions and focused reviews, and its full audit mode
for explicit codebase audits, comprehensive reviews or requested audit reports.
Preserve upstream evidence thresholds, independent verification and validators.

Use the bound [workspace](../workspace/SKILL.md). Full audit artifacts require a
declared real local output directory supported by upstream. Keep its run files
there and link useful results from the existing TH context. A Page URL is a
context locator, not a filesystem output path. Installation alone authorizes
preparation. A subsequent audit follows the operator's requested scope.

Use the host's actual sandbox for upstream's bounded local execution contract.
If required isolation or a native capability is unavailable, follow upstream's
pending-validation path and report the exact missing observation or capability.
Preserve native permissions, operator authorization and Main's coordination.

## Report the result

Report the provider source/revision, installation scope and actual readiness.
For an assessment, retain upstream findings, dispositions, coverage and material
limits. Main assesses recommendations and owns follow-up decisions. A finding
or successful validator does not grant implementation or publication authority.

Example requests include `cloudflare-security install`,
`cloudflare-security update`, and `cloudflare-security review the MCP dispatcher`.
